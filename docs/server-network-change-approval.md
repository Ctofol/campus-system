## 二、申请事项

1. 请在服务器所属平台的安全组或外层防火墙中，新增以下入站规则：

   - 协议：TCP
   - 公网端口：443
   - 来源：`0.0.0.0/0`
   - 策略：允许
   - 用途：校园运动系统 HTTPS 访问

2. 保留 TCP 80，用于 HTTP 自动跳转 HTTPS；正式业务不会通过 HTTP 传输账号或隐私数据。

3. 请确认 Wazuh Dashboard 由原 443 调整到 8443 的安排。当前 Wazuh 服务仍正常运行，8443 暂未对公网开放；如需远程访问，建议只允许指定管理 IP，不建议对全网开放。

4. 待 443 验收通过后，建议取消 320、321 的公网访问，仅保留服务器本机访问：

   - `127.0.0.1:320`：学生端静态服务
   - `127.0.0.1:321`：管理端静态服务

## 三、申请理由

系统包含登录、定位、相机、人脸核验、文件上传等功能。浏览器、H5及小程序环境对这些能力通常要求使用可信 HTTPS。若不开放 443：

- 域名只能通过非标准端口或 HTTP 访问；
- 定位、相机及人脸相关功能可能被浏览器限制；
- 登录和上传数据无法通过标准 HTTPS 入口传输；
- 不利于后续正式上架和安全验收。

## 四、端口与访问设计

| 端口 | 是否公网开放 | 用途 |
| --- | --- | --- |
| 22 | 按现有管理策略 | SSH 运维，建议限制来源 IP或使用密钥 |
| 80 | 是 | HTTP 跳转 HTTPS |
| 443 | 申请开放 | 学生端、管理端和 API 的统一 HTTPS 入口 |
| 320 | 验收后关闭公网 | 学生端内部服务 |
| 321 | 验收后关闭公网 | 管理端内部服务 |
| 8443 | 默认不开放公网 | Wazuh Dashboard |
| 18721 | 不开放公网 | FastAPI 后端，仅监听 `127.0.0.1` |

管理端不额外申请公网端口，由 Nginx 在 443 上按路径分流：

```text
https://campus.gzyichenai.com/         -> 学生端 320
https://campus.gzyichenai.com/admin/   -> 管理端 321
https://campus.gzyichenai.com/api/     -> 后端 18721
https://campus.gzyichenai.com/manage/  -> 后端 18721
```
